# JobFinder — отобранная удалённая работа

Сбор публичных вакансий hh.ru с полными описаниями, фильтрацией нежелательных обязанностей и аналитикой по сгруппированным должностям, языкам программирования, технологиям, инструментам и иностранным языкам. Токен и платные функции hh.ru не требуются.

## Запуск

Нужен Node.js 24+ со встроенным `node:sqlite`.

```bash
npm install
npm run dev
```

Сбор запускается вместе с сервером. Отдельный процесс, работающий без браузера и веб-сервера:

```bash
npm run collect
```

Отдельный процесс использует `node --watch`: изменения импортируемых правил и словарей перезапускают его. Все экземпляры делят блокировку SQLite, поэтому запросы к hh.ru выполняет один владелец. Прогресс сохраняется после остановки.

## Правила отбора

- Ищем все профессии с форматами `REMOTE` или `HYBRID`. Это не строгий IT whitelist: SMM, маркетинг, управление, клиентский сервис, бухгалтерия и другие роли допускаются.
- Чистый офис, разъездная работа, закрытые объявления, продажи, обзвоны, обычные колл-центры, преподавание и сопровождение онлайн-обучения исключаются.
- Техническая поддержка без продаж и исходящих обзвонов допускается. Учитываются отрицания: «без холодных звонков» само по себе не причина отклонения.
- Название работодателя и отрасль не являются самостоятельным основанием исключения: разработчик в образовательной компании или аналитик продаж могут пройти отбор, если сама работа не является продажами/преподаванием.
- В интерфейсе по умолчанию показаны только вакансии, у которых единственный формат — `REMOTE`. Флажок **«Показывать гибрид и полуофис»** по умолчанию выключен; он включает также гибрид и сочетания удалёнки с офисом.

Отбор эвристический, по явным правилам. Неоднозначные объявления и ограничения по месту работы нужно проверять по исходному тексту. Проверки капчи не обходятся.

## Двухэтапный сбор

1. Получаем публичную выдачу `https://hh.ru/search/vacancy`, извлекаем `HH-Lux-InitialState`, проверяем применённые даты, регион и форматы. Заголовки исключённых ролей отсеиваются сразу.
2. Подходящие кандидаты ставятся в очередь полных карточек. Они ещё не считаются сохранёнными вакансиями и не участвуют в статистике.
3. Загружаем `https://hh.ru/vacancy/{id}`. Из `vacancyView.vacancyFull.vacancy` получаем текст, ключевые навыки и актуальные форматы. Проверяем соответствие ID.
4. Повторно проверяем обязанности. Только прошедшая обе проверки вакансия сохраняется и попадает в аналитику. Отвергнутые объявления не сохраняют текст/карточку; для дедупликации и счётчиков остаются только ID, причина и время проверки.

Поиск и полные карточки чередуются внутри самого важного доступного уровня очереди (две из трёх позиций отдаются описаниям, если они есть). Сначала полностью удалённые вакансии: отдельные запросы по работе с блогерами (`блогер`, `influence`, `инфлюенс`), затем разработка, безопасность, QA и смежные роли, остальные профессии, после них — гибрид. Запросы форматов разделены; смешанные карточки откладываются в очередь гибрида. Профессии и задания с меньшим приоритетом не удаляются.

Между запросами — минимум 10 секунд. При 403/429 или капче даже с HTTP 200 весь сбор ждёт 5, 10, 20, затем до 30 минут, с учётом более длинного `Retry-After`. После блокировки обычный интервал увеличивается до 20–60 секунд и постепенно возвращается к 10 секундам после успешных запросов. Неудачи отдельных карточек/парсинга откладывают само задание; 5xx приостанавливает общий поток минимум на минуту. После шести неудач задание помечается ошибочным. Возобновление не сбрасывает общую паузу. В интерфейсе видны интервал, состав очереди, число пропущенных проверенных карточек, HTTP-статус и короткий заголовок последнего ошибочного ответа. Тело страницы, cookies и секреты в диагностике не сохраняются.

Очередь карточек уникальна по ID вакансии, поисков — по URL и типу задания, без привязки к циклу. Повторное обнаружение не сбрасывает срок повторной попытки. Сохранённые карточки с неизменными краткими полями не запрашиваются 3 дня; изменение заголовка, даты, работодателя, места, опыта, зарплаты или формата вызывает повторную проверку. Отклонённые ID проверяются повторно не ранее суток (закрытые — недели). Все эти интервалы заданы в `server/collector-policy.ts`.

Первичный проход охватывает 30 дней. Каждые 6 часов добавляется поиск с даты предыдущего запуска с перекрытием в один день; он не ждёт завершения старой очереди. Задания первого прохода остаются и постепенно выполняются. Выдачи свыше 2000 результатов делятся по датам, затем по субъектам России и опыту. Словарь регионов берётся из публичного `/areas/113`.

При первом запуске новой версии очередь переносится транзакционно: старые поисковые задания остаются в истории со статусом `superseded`, ожидающие карточки получают новые приоритеты и дедуплицируются. Сами вакансии, описания, навыки и даты получения эта миграция не меняет. Существующая пауза после блокировки сохраняется.

## Словари и аналитика

- `server/selection.ts` — причины исключения и правила анализа обязанностей.
- `server/knowledge.ts` — синонимы должностей и словарь навыков с категориями и алиасами.
- `server/hh-detail.ts` — извлечение проверяемого текста из полной карточки.

После изменения словарей можно применить новые правила и группировку к уже сохранённым карточкам: `npm run recheck-data`. Команда временно приостанавливает сбор, обновляет производные метки и исключает записи, переставшие соответствовать правилам; исходные даты получения у оставшихся записей сохраняются.

Например, `Senior Frontend developer`, `Frontend-разработчик (React)` и `Разработчик React` объединяются в **Frontend-разработчик**. Системный, бизнес- и продуктовый аналитики разделены; Frontend, Backend и Fullstack также разделены. У неизвестных должностей нормализуются регистр, пробелы и часть маркеров уровня. Не используется агрессивное объединение всех похожих строк. Исходные названия доступны в группе и в карточке.

Навыки извлекаются из структурированных навыков hh.ru, названия и полного описания. Алиасы вроде JS/JavaScript и Postgres/PostgreSQL объединяются. Одна вакансия учитывается один раз для каждой метки. Сохраняются категория, источник и короткий фрагмент текста, на котором основана метка. Это упоминания, а не гарантированно обязательные требования. Словарь ограничен, часть инструментов может не распознаваться; все исходные навыки hh.ru и описание доступны для проверки.

Статистика относится только к сохранённой выборке. Предварительные счётчики hh.ru до исключений не выдаются за количество подходящих вакансий. Медиана зарплат — нижняя граница в рублях за месяц, явно указанная на руки; размер зарплатной выборки показывается рядом. Проценты пересчитываются после фильтров. Вакансии можно листать постранично.

## Приоритетные направления

Страница `/?view=priority` доступна из меню и блока на главной. Веб, разработка ПО, influence/блогеры, кибербезопасность, DevOps, QA, данные и продукт/UX определяются словарём `src/lib/priorities.ts`. Он проверяет название, структурированные навыки и рабочие задачи в описании; показывает источник и фрагмент каждого совпадения. Словарь можно расширять в этом файле.

Классификация выполняется при чтении: уже накопленные и новые вакансии видны автоматически, миграция и пересохранение данных не нужны. Счётчики направлений учитывают общие фильтры до выбора направления. Одна вакансия может подходить нескольким направлениям, но в итоговом списке и метриках считается один раз. Должности, зарплаты и навыки пересчитываются для выбранной группы; есть пагинация и поиск. Гибрид по умолчанию выключен.

Вкладка **«Инфлюенс»** (`/?view=influence`) отдельно показывает работу с блогерами: поиск, интеграции и influencer-кампании. Поиск, сброс фильтров, статистика и пагинация остаются в рамках направления `influence`. Показаны причины отбора, инструменты и иностранные языки; красное оформление сохранено.

`GET /api/analytics?priority=any` возвращает все приоритетные; вместо `any` можно передать `web`, `development`, `influence`, `security`, `devops`, `testing`, `data` или `product-design`. Без `priority` сохраняется общая выборка. Дополнительный блок ответа `priority` содержит счётчики и объяснения для текущей страницы. Правила эвристические, полнота зависит от собранных вакансий.

## Хранение и сброс

База: `data/jobfinder.sqlite` (WAL), исключена из Git и веб-доступа. Хранятся карточки, описания, навыки, группы, первая/последняя дата получения, очередь и состояние сбора. ID вакансии исключает дубли. При изменении карточки отбор выполняется заново; вакансия, переставшая соответствовать правилам, удаляется из основной выборки.

**Явное обнуление вакансий, очереди и старых счётчиков:**

```bash
npm run reset-data
```

Команда сначала ставит сбор на паузу; если запрос ещё выполняется, нужно повторить через 20 секунд. Она очищает данные транзакционно и ставит текущую версию правил. Не запускается автоматически на существующей базе. Все отдельно запущенные сборщики должны использовать текущий код; старые процессы перед сбросом нужно остановить. `-- --paused` оставляет новую базу на паузе.

## Проверки

```bash
npm test
npm run lint
npm run build
npm run audit-data
```

Тесты проверяют отбор, отрицания и контекст, нормализацию названий, синонимы навыков, работу с полными карточками, двухэтапное сохранение, пагинацию, зарплаты, очередь, перезапуск и блокировку между процессами. `audit-data` открывает реальную базу только для чтения и проверяет каждую сохранённую вакансию по текущим правилам.

`scripts/check-ui.mjs` проверяет интерфейс через локальный CDP браузера на порту 9236. Обработчики API подключены к Vite dev/preview; `dist` содержит только клиент, для размещения нужен отдельный сервер. Vite preview предназначен для локальной проверки.
