# Проверка сборщиков — 16.11.2026

Проверены реальные счётчики, очереди и журнал работающего приложения, затем публичные запросы проблемных источников с этой машины. Сетевой отказ здесь не означает глобальную недоступность сервиса. Нулевое число сохранённых вакансий не считается поломкой: действуют фильтры веба, языка, географии, удалёнки и уровня.

## Что изменено в хранении и запуске

В активном реестре девять треков, включая hh. Удалённые источники больше не планируются и не появляются в интерфейсе. Старые задания получают статус `retired`, прежние тяжёлые ATS-запросы — `superseded`; старые логи остаются для диагностики. Вакансии, источники уже сохранённых записей и личные отметки не удаляются. Паузы после 403/429 сохраняются при миграции URL и перезапуске.

## Документация, использованная при исправлении

- [Greenhouse Job Board API](https://docs.greenhouse.io/job-board.html): список без описаний и отдельная карточка, публичные GET без авторизации.
- [Lever Postings API](https://github.com/lever/postings-api): пагинация `limit` / `skip`.
- [Remotive Public API](https://github.com/remotive-com/remote-jobs-api) и [XML-ленты](https://github.com/remotive-com/remote-jobs-feed).
- [Himalayas API](https://himalayas.app/api): документированные публичные search/feed endpoints.
- [Remote OK JSON feed](https://remoteok.com/api).
- [Telegram TDLib: авторизация](https://core.telegram.org/tdlib/getting-started).

Проверки: тесты парсеров, пагинации, миграции очередей и сохранности вакансий/откликов; общий набор тестов; lint, production build и аудит реальной базы. Публичные запросы и успешная обработка исправленными воркерами проверены отдельно от тестовых ответов.
